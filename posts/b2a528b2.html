发表于 2026-03-28 分类于 强化学习 阅读次数： 本文字数： 4.8k 阅读时长 ≈ 18 分钟
agile earth observation satellite scheduling problem

概述

带有时间依赖的多轨道敏捷卫星观测调度问题旨在从几个连续轨道中选择多个任务，并在不违反约束的情况下确定选择任务的观测序列和观测时间。轨道是指卫星绕地球旋转的时间间隔，轨道的起点可以设置为卫星飞离地球地影或经过一个特定纬度或经度的时间，卫星能够从多个轨道观测给定任务，因此每个任务具有多个可见时间窗口。

问题描述

假设与变量

  • 卫星仅有一个传感器

  • 所有任务均为点目标

  • 不考虑存储和功率限制。

  • 不考虑观测数据下传过程。

| 变量          | 定义                                                 |

| ————- | —————————————————- |

| $task_i$      | 待调度的观测任务 $i$                                 |

| $tw_i$        | 任务 $i$ 的可见时间窗口                              |

| $tw_i^s$      | 可见时间窗口的开始时间                               |

| $tw_i^e$      | 可见时间窗口的结束时间                               |

| $p_i$         | 任务 $i$ 的优先级，即观测该任务获得的奖励           |

| $d_i$         | 任务 $i$ 所需的持续时间                              |

| $ob_i$        | 任务 $i$ 的观测开始时间                              |

| $oe_i$        | 任务 $i$ 的观测结束时间                              |

| $trans_{ij}$  | 两个连续任务 $i$ 和 $j$ 之间的姿态转换时间          |

| $x_i$         | 二元变量，表示任务 $i$ 是否被观测                   |

数学公式

AEOSSP的目标函数是最大化观测任务的优先级总和:

目标函数：

$$

\max \sum_{i=1}^{N} p_i x_i \tag{1}

$$

约束条件：

$$

\begin{align*}

ob_i - tw_i^s &\geq 0, \quad \text{if } x_i = 1 \tag{2} \

tw_i^e - oe_i &\geq 0, \quad \text{if } x_i = 1 \tag{3} \

ob_i + d_i &= oe_i, \quad \text{if } x_i = 1 \tag{4} \

ob_j - (oe_i + trans_{ij}) &\geq 0, \quad \text{if } x_i = 1, x_j = 1 \tag{5} \

x_i &\in {0,1}, \quad \forall i \in {0,1,2,\dots,N} \tag{6} \

tw_i^s, tw_i^e, p_i, d_i, ob_i, oe_i, trans_{ij} &\geq 0 \tag{7}

\end{align*}

$$

公式 (2) 和 (3) 表示任务的观测开始时间和结束时间应在可见时间窗口之内。公式 (4) 表示任务的开始时间、结束时间与持续时间之间的关系。公式 (5) 表示两个连续任务之间的转换时间约束。公式 (6) 和 (7) 限定了变量的取值范围。

姿态转换时间计算方法

概述

姿态转换时间采用分段线性函数进行计算，以模拟真实敏捷卫星的物理特性。核心计算公式为：

$$t_{i,j} = \lambda + \frac{\Delta \theta_{i,j}}{\nu}$$

其中：

  • $t_{i,j}$：从观测 $i$ 到观测 $j$ 的姿态转换时间（秒）

  • $\Delta \theta_{i,j}$：姿态角总变化量（度）

  • $\lambda$：稳定时间常数（秒）

  • $\nu$：角速度（度/秒）

姿态角变化量计算

总姿态角变化量 $\Delta \theta_{i,j}$ 由滚转角和俯仰角的变化量组成：

$$\Delta \theta_{i,j} = |\Delta \theta^{roll}| + |\Delta \theta^{pitch}|$$

其中：

  • $\Delta \theta^{roll}$：滚转角变化量

  • $\Delta \theta^{pitch}$：俯仰角变化量

分段计算规则

根据总姿态角度变化 $\Delta \theta_{i,j}$ 的大小，采用不同的参数组合：

| 角度范围 | 稳定时间 $\lambda$ (秒) | 角速度 $\nu$ (度/秒) | 物理含义 |

| :—: | :—: | :—: | :— |

| $\Delta \theta \leq 10°$ | 11.66 | $\infty$ | 微小调整：转动时间可忽略，主要耗时为稳定 |

| $10° < \Delta \theta \leq 30°$ | 5 | 1.5 | 慢速机动：稳定时间减少，转动速度较慢 |

| $30° < \Delta \theta \leq 60°$ | 10 | 2.0 | 中速机动：稳定时间增加，转动速度加快 |

| $60° < \Delta \theta \leq 90°$ | 16 | 2.5 | 快速机动：稳定时间更长，转动更快 |

| $\Delta \theta > 90°$ | 22 | 3.0 | 极限机动：稳定时间最长，转动速度最快 |

MDP描述

AM作为任务选择的策略，用于指导解的构造过程。初始时，构造过程从一个空集合开始，通过BPM重复选择任务。在决策点 $dp_t$，BPM根据当前状态选择一个任务，将其插入观测序列。随后，根据所选任务更新状态并进行约束检查。观测序列的插入过程持续进行，直到无法再添加任何任务为止，从而完成解的构造过程。

任务选择仅由前一步的决策决定，因此我们可以将AEOSSP建模为一个MDP，该MDP包含四个基本组成部分：状态集 $S$、动作集 $A$、状态转移概率函数 $T$ 和奖励函数 $R$。具体说明如下：

  • 状态集 $S$：包含决策点 $dp_t$ 时卫星的状态和待调度任务的状态。

  • 动作集 $A$：表示选择任务的行动。

  • 状态转移概率函数 $T$：表示在某一状态下执行某个动作后所得到的概率分布。

  • 奖励函数 $R$：表示观测序列的总优先级。

训练方法

使用带rollout基线的REINFORCE算法来训练策略模型以获得最优策略参数，并使用adam优化器进行更新。

动态特征和静态特征

我们使用一个元组 $\langle x_t^i \rangle = (s_i, d_t^i)$ 来表示每个任务 $i$，其中 $s_i$ 代表任务的固有属性，而 $d_t^i$ 是任务 $i$ 在时间 $t$ 的动态变量。参数 $s_i$ 包含四维特征：

$tw_i^s, tw_i^e, l_i, p_i$。而参数 $d_t^i$ 包含二维参数：前一个任务的结束时间 $T_{t-1}^e$ 和任务 $i$ 在时间 $t$ 的状态值 $state_t^i$。$state_t^i$ 有三种状态：1 表示已调度，2 表示已删除，0 表示待调度。

多时间窗处理方法

问题描述

每个观测任务可能具有 0 个、1 个或多个可见时间窗口。在 MDP 建模中，每个任务对应一个节点，模型需要在每个决策步选择一个任务。多时间窗的存在使得可行性判断变得复杂。

设计方案：每任务单节点 + 环境动态选择窗口

核心思路

  • 模型视角：每个任务对应一个节点，模型不需要感知该任务具体有几个时间窗

  • 环境视角：在每个决策步，环境遍历每个待调度任务的所有时间窗，判断是否存在至少一个可行窗口

  • 窗口选择：当任务被选中时，环境自动选择”最早可行”的时间窗作为该任务的执行窗口

可行性判断逻辑

在决策点 $dp_t$，当前时间为 $T_{t-1}^e$（上一个任务的结束时间），当前姿态为 $(\text{roll}, \text{pitch})$。对于待调度任务 $j$：

$$

\text{feasible}(j) = \exists, tw_k \in \text{windows}(j) \text{ 使得}:

$$

$$

T_{t-1}^e + trans(\text{current_attitude}, \text{task}_j) + l_j \leq tw_k^e

$$

$$

\text{且} \quad T_{t-1}^e + trans(\text{current_attitude}, \text{task}_j) \geq tw_k^s

$$

其中：

  • $trans(\cdot, \cdot)$ 为姿态机动时间（由分段线性函数计算）

  • $l_j$ 为任务 $j$ 的持续时间

action_mask 更新流程

  1. 在每一步 $t$，遍历所有 $state = 0$（待调度）的任务

  2. 对每个任务，遍历其所有时间窗

  3. 若存在满足条件的窗口 → task 保留在 action_mask 中（值为 True）

  4. 若所有窗口都不满足 → task 标记为 $state = 2$（已删除），从 action_mask 中移除

优点

  • 模型结构简单，节点数固定（N 个任务）

  • 多窗逻辑完全封装在环境内部

  • 未来切换至 AM 等更复杂模型时无需修改环境

后续扩展

  • 可改为选择”最优”窗口而非”最早”窗口（如最大化时间裕度）

  • 可在模型输入中增加”可用窗口数量”作为额外特征

马尔可夫模型

有限MDP

系统有有限个状态，未来只依赖当前状态，状态转移由一个固定转移概率矩阵来描述。

串联MDP

多个随机过程/多个马尔可夫层依次作用。

串联马尔科夫链（过程串联）

一个系统的输出状态作为下一个马尔科夫链的输入条件。

例如：

  • 第一层 Markov 决定“大状态”（如环境：忙/空闲）

  • 第二层 Markov 在大状态下决定“细状态”（如误码水平）

这往往等价于一个更大的联合状态空间马尔可夫链（状态=(层1状态, layer2状态)），但“串联”强调结构分解/层次化。

串联马尔可夫模型

一个Markov的输出，作为下一个Markov的观测或者驱动。

  • 有限马尔可夫模型：强调“状态数有限 + 马尔可夫性”，是一个基本对象。

  • 串联马尔可夫模型：强调“多个马尔可夫结构串起来/分层”，是一种组合/构造方式，通常仍可转化为一个更大的有限马尔可夫模型来分析。

正向暗示

在午睡后半睡半醒的状态下，梦到各种各样光怪陆离的东西，这是一种非常普遍且正常的生理现象。这背后主要涉及睡眠科学中的几个关键概念。

简单来说，这是因为你的大脑和身体在睡眠与清醒之间没有完全同步“切换”，导致梦境与现实短暂地重叠了。

🧠 核心原因：REM睡眠与睡眠瘫痪

  1. 快速眼动睡眠（REM）是梦的“工厂”
    梦境主要发生在快速眼动睡眠（REM）阶段。在这个阶段，你的大脑活动非常活跃，几乎和清醒时一样，但身体肌肉却处于一种暂时性的“瘫痪”状态（也叫肌张力丧失），这是为了防止你把梦里的动作做出来而伤到自己。

  2. 午睡容易直接进入REM睡眠
    当你非常疲惫或睡眠不足时，大脑会“抄近道”，更快地进入REM睡眠阶段，这被称为“REM睡眠反弹”。所以，即使是短暂的午睡，也可能让你迅速进入生动梦境的“制作车间”。

  3. 半睡半醒是意识与身体的“不同步”
    午睡醒来时，你的意识可能已经部分清醒，但大脑还没完全从REM睡眠中脱离。这时就可能出现两种情况：

    • 睡眠瘫痪（俗称“鬼压床”）： 你的意识醒了，但身体的“瘫痪”状态还没解除，导致你感觉动弹不得。
    • 醒后幻觉： 梦境的画面、声音或感觉延续到了清醒状态，让你感觉看到了人影、听到了声音，或者感觉房间里还有别人。

这种大脑清醒了但身体还在“梦中”，或者梦境内容“溢出”到现实感知的状态，就是你感觉“半睡半醒”并遇到各种奇怪东西的根本原因。

✨ 为什么梦里的东西“各种各样”？

除了上述核心机制，还有一些因素会让你在半梦半醒间的体验更加丰富和奇特：

  • 创造力爆发的N1阶段： 在刚入睡的N1阶段（入睡状态），大脑的控制力减弱，思维变得非常发散和灵活，像“思绪漫游的旋钮被调到最高”。这个状态是激发创造力的黄金时期，容易产生各种新奇、跳跃的联想和意象。
  • 大脑的“默认网络”被激活： 在半梦半醒时，大脑中负责逻辑和现实检验的区域（如前额叶皮层）还未完全上线，而负责联想和记忆整合的区域（如海马体）却很活跃。这导致各种看似不相关的记忆碎片、情绪和想象被随机组合在一起，形成了荒诞离奇的梦境内容。
  • 压力与情绪的“加工厂”： 白天的压力、焦虑或过度兴奋的神经状态，都会在睡眠中被大脑处理和释放，从而投射到梦境中，使其内容更加复杂和情绪化。

💡 如何改善这种状态？

这种现象通常是无害的，但如果频繁发生并影响你的休息质量，可以尝试以下方法：

  • 规律作息： 保证夜间有充足、高质量的睡眠，避免过度疲劳。
  • 管理压力： 午睡前通过深呼吸、冥想等方式放松心情，避免带着紧张情绪入睡。
  • 优化午睡： 将午睡时间控制在20-30分钟，避免进入深度睡眠后再被唤醒，这样可以减少睡眠惯性和混乱感。
  • 改善睡姿： 尽量侧卧，避免仰卧或手压胸口，这有助于减少睡眠瘫痪的发生。

如果这种情况非常频繁，并伴有白天极度嗜睡、情绪激动时突然肌肉无力等症状，建议咨询医生，以排除潜在的睡眠障碍。
